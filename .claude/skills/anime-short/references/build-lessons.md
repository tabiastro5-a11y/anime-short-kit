# 作っていて見つけた不具合・原因・直し方・速くする方法（2026-11-23〜）

ここは**技術的な不具合**と**作業の速さ**の記録。新しく見つけたら1行足す。

## 絵の不具合
| 症状 | 原因 | 直し方 | 次から |
|---|---|---|---|
| 天井ごしに空が見える（待合室・店内） | `boxGeo` は既定で**下の面を作らない**。下から見上げる天井が透明になる | 天井は `bx(..., tile, true)`（bottom=true） | 天井・棚の下・机の裏など、下から見える箱は bottom=true |
| 「高額当選」の画面が客に見えた | 寄りの絵を撮りやすい向きで画面を置いた（話の筋を見ていなかった） | 画面は店員側（+z）、寄りは店員の肩ごしから | カット表の「見える向き」の欄で決めてから置く |
| ゴミ箱のカットで店員の体が消えた | 部品にない姿勢（頭から入る）を効果の絵（足だけ）で代用 | 新しい演技 `reach`（身を乗り出して腕を入れる）を toon.ts に足す | できない姿勢は先に一覧にして部品を作る。体を消さない |
| 店員がゴミ箱と逆に傾く | 人物の絵の左右は、カメラから見てどちら側に物があるかで決まる。+z を向いて見ると +x が画面の**左** | `{...place, mirror: true, key: key + "\|m"}` で左右反転 | 物に向かう演技は、カメラから見た左右を確かめて mirror を付ける |
| 画面の切り替えでカメラがセットを突き抜ける | 「滑る」（glide）で反対側のカメラ位置へ移った | その切り替えだけ `cut: true` | 向きが 90° 以上変わる切り替えは cut |
| 頭ごしの人の頭が画面をふさぐ | カメラが人物に近すぎ、頭がそのまま大きく写る | 人物を画面の端に寄せる（カメラと見る点の線から外す） | 頭ごしは「頭は画面の端 1/4、話す人は 1/3」 |
| 顔のアップが字幕に重なる | 見る点が顔の高さ | 見る点を少し下げて顔を上へ（顔の中心を高さ 35〜55 %） | climax-playbook の決まり |
| 財布の寄りが映らない | カウンターがカメラと財布の間にあった | カメラをカウンターと店員の間に置き、財布の絵を小さく近くに | 手元の寄りは、間に物がないか静止画で確かめる |
| 最後の寄りが店員の顔へ行く | `landPush` は見る点に向かって寄る。見る点が店員だった | 別のカメラ（見る点＝くじ）へ滑ってから寄る、ピントもくじへ | 寄る先＝見る点。寄る先が変わるなら別のキー |
| 待合室の椅子の背もたれが店員を隠す | 椅子の向き（背もたれが手前） | 椅子を 180° 回す | — |
| 釣り針が客の頭に隠れる | くじの高さが頭と同じ | くじを頭の横の高さまで持ち上げる | — |
| 暗い所が暗すぎる（店内の p5） | 照明ではなく、**頭ごしの客の黒い髪**が原因だった | 髪を茶色に（参考の頭ごしも茶色） | 数字が照明で動かない時は、何が暗い／明るいのかを絵で探す |
| 夢・寝室・道の数字が照明で動かない | 明るさを決めていたのが光の当たらない物（光る月、空、画面を覆う車、壁の色） | 比較画像で原因を見つけ、物の色・形を直す | 計測で外れたら、まず元動画と並べて見る |
| 看板の文字が借りた GPU とこの PC で違う | Canvas の字が OS の字（Windows：游ゴシック、Linux：Noto）に頼っていた | Google Fonts の Noto Sans JP を読み込み、字を全部それで描く（`loadKit` で読み込み完了を待つ） | Canvas の文字は必ずプロジェクトで読み込んだ字を使う |

| 椅子に座っているのに体が椅子を貫通する（待合室） | 座る姿勢 `sit` は**地面に座る**作り（腰が足の 0.1 m 上）。椅子の位置に置くと座面が胸を横切る | toon.ts に `seatH`（腰の高さ。椅子は 0.95 頭身＝約 0.46 m）。札は座面の**中**に置き、座面の板が太ももを横切るように（前から見て座って見える）。座面の手前に出すと「椅子の前に立っている」ように見える | 椅子に座らせる時は seatH、札は座面の中 |

## 道具・作業の不具合
（2026-11-24 追記：借りた GPU での v4）
- **道具が Windows の改行（CRLF）で送られて、借りた機械で止まった**（`set: -: invalid option`）。直し：`scripts/remote/*` を LF にして `.gitattributes` に `*.sh text eol=lf`。
- **ドライバーが新しい機械（NVIDIA 610）は Vulkan が使えない**（Chrome：`vkCreateInstance() failed: -7`）。直し：`setup.sh` で `libegl1 libgles2 libgl1` を入れると `angle-egl` で動く（8つ並べて 1929 コマ約35秒）。`setup.sh` が自動で試して `gpu.env` に書く。
- **つなぎ合わせが「p241 がない」で止まった**：`while read` の中の ffmpeg が標準入力（ranges.txt の続き）を食べていた。直し：`ffmpeg -nostdin`。
- **ドライバー 610 の機械で書き出した動画に、人物・月・写真のまわりへ黒や白の四角が出た**（静止画ではきれい、8つ並べた書き出しでだけ出る）。
  ドライバー 580 の機械では同じ道具・同じ方式（angle-egl）できれいだった。直し：`vast.py offers` はドライバー 600 以上の機械を出さない。
  ChatGPT の絵に残る「ほぼ透明な暗い点」（透明度1〜7）も消すようにした（`slice_character.py` の load）。
- **四角の本当の原因（2026-11-24）**：ドライバー 580 の機械でも出た。人物・効果の絵を描く 2D キャンバスが GPU 描画だと、8つ並べた書き出しで透明が壊れる。キャンバスは `getContext("2d", { willReadFrequently: true })`（CPU 描画）で作る。これで消えた。
- **書き出した動画は、送る前にコマを取り出して自分で見る**（60コマごとに並べた一覧 `out/<回>/check/vv_sheet*.jpg`）。
  この PC の静止画がきれいでも、借りた機械の動画がきれいとは限らない。`short_qa.py` は黒・白・止まりしか見ないので、四角は通ってしまう。
- かかった時間：借りてから止めるまで約20分（うち原因調べ約12分）。次からは準備5分＋書き出し2分の見込み。

## 速くする方法（効いた順）
- **直した所だけ書き直した実測（2026-11-24、待合室の座り方、この PC のみ・GPU を借りずに）**：依頼から完成まで **7分49秒**。内訳：原因調べと直し 約1分、静止画で確認 2回（1回目は「椅子の前に立って見える」ので直し直し）約2分、v2 を8部分に切る（**v2 だけの1回きりの準備**）48秒、2部分の書き直し 88秒（全体なら約5分）、つなぎ方の不具合2つを直して確認 約2分、QA 約1分。**次から（部分が残っている v3 以降）は、直し＋確認＋書き直し＋つなぎ＋QA で約4分**の見込み。
1. **借りた GPU で 8 つ並べて書き出す**：手元 5 分 → 約 76 秒（＋送受信）。手元と見分けがつかないことを確認済み。**使い終わったらすぐ返却**（`remote.sh done`）。
2. **書き出す前に 4 枚シート**（全カット×4枚、約 100 枚）：書き出してから見つけるより、何度もやり直さずに済む。借りた GPU なら 1〜2 分。
3. **素材のまとめを使い回す**（`out/.bundle-cache/`）：変わっていなければ 0 秒。
4. **見た目の合わせ込みは 1 回で全部の場所を測る**：場所ごとに 1 項目ずつ直し、1 回の静止画書き出しで全部の場所をまとめて測る。
5. **数字が動かない時はすぐ比較画像**：同じ値を何度もいじらない。
6. **声は作り直さず、速さだけ変える**：`tighten.py --tempo` は録り直し不要（1.15→1.12 で 6 字/秒に）。
