新しい回は、cartoon-3d-short の `templates/bridge/` をコピーしてから、和の部品を `templates/japan/` から上書きする。
- `templates/japan/toon.ts`：人物（和装・ちょんまげ・日本髪・手ぬぐい・野良着）と**作業の動き**。bridge の toon.ts の上位互換。
- `templates/japan/story.ts`：01_inamura のカット表（`landPush` など見せ場のカメラ部品の見本。中身は回ごとに書き直す）。
- `templates/japan/japan.ts`：和の建物と地形（民家・町家・蔵・鳥居・神社・石段・石垣・松・稲むら・堤防・工事現場）。
- 最新版は、それを使った一番新しい回。回で直したら、ここにもコピーして戻す。
- 見本の確認用の絵：`WorkSheet`（作業の動き・演技のポーズ）、`CastSheet`（人物）のコンポジション。`COMP=WorkSheet node scripts/bridge-stills.mjs out/x_ 0 1`

## 作業の動き（toon.ts `WORK`、cast.ts `workCycle`）
`bodyFront(p, outfit, { act: { kind, k, load } })` で、両腕・体の傾き・道具がまとめて決まる。k は 0〜1。

| kind | 何をしている | k の意味 | 時間の付け方（`workCycle`） |
|---|---|---|---|
| `tenbin` | 天秤棒で土のかごを2つ担ぐ（歩きながら） | 歩きの位相 | 歩きの phase をそのまま渡す。`mode: "stroll"` と一緒に |
| `mallet` | 掛矢（大きな木槌）で打ち固める | 0 振り上げ → 1 打つ | 持ち上げ 0.55、ため 0.15、打ち下ろし 0.12（`STRIKE_AT` 0.82 で当たる） |
| `hoe` | 鍬で耕す | 0 振り上げ → 1 打つ | mallet と同じ |
| `shovel` | 鋤で土を掘って投げる | 0 刺す → 1 投げる | 刺す・持ち上げ・投げ・戻す |
| `sapling` | 松の苗を植える | 0 胸の前 → 1 地面 | 一度下ろして止める |
| `rope` | 綱を引く（蛸＝丸太の突き固めを吊る） | 0 腕を上 → 1 引き下ろす | 上下のくり返し |
| `ignite` | 松明で右側の物（稲むら・のろし）に火をつける。`v` は炎のゆらぎ 0〜5 | 0 松明を肩で掲げる → 1 腕を右下へ伸ばす | 火が付く 0.5秒前から伸ばし、付いて 0.15秒後から 0.35秒で戻す（cast.ts の梧陵） |
| `kime` | 決めポーズ：両手を腰に、ひじを張る（自己紹介・見せ場） | 0 自然に立つ → 1 決め | 言葉の頭の 2f 前から 0.2秒で |
| `present` | 右側を手のひらで示す（「これが〜だ」） | 0 → 1 腕を伸ばして開く | 0.25秒で |
| `armsCrossed` | 腕組み（考える・頑固・待つ） | 0 → 1 | 0.3秒で |
| `cheer` | 両手を上げて喜ぶ | 0 → 1 | 0.2秒で（くり返すと「バンザイ」） |
| `think` | 片手をあごに、もう片手でひじを支える | 0 → 1 | 0.3秒で |

- 火をつける人は、燃やす物の**画面の左側**に立たせる（松明は右手側に伸びる）。絵のカードの右端からはみ出さない長さにしてある。
- `torchAt(p, u, 手の位置, 角度, v)`：松明の絵だけを使いたいときの部品。

- `load: 0` で空のかご・空の鋤。
- 打つ瞬間には `dustAt()`（cast.ts）で土ぼこりのカードを出し、打つ音を同じフレームに置く。打つ時刻は `(n + STRIKE_AT - off) * period`。
- 正面の絵だけ。横向きで歩く人に道具を持たせると消えるので、作業の人は正面（`front`）で置き、運ぶ人はカメラに向かって歩かせる。

## 新しい動きを足すとき
1. toon.ts の `WorkKind` に名前を足し、`WORK` に `{ lean, pose }` を書く（`swingPose` / `twoHands` / `longTool` を使い回す）。
2. cast.ts の `workCycle` に時間の付け方を足す。
3. `WorkSheet` に出して、k = 0 / 0.5 / 1 の3枚で読めるか確かめる（カードの上端からはみ出さないこと）。
4. この表に1行足す。

## 群衆（たくさんの人）を軽く描く仕組み（cast.ts、2026-11-23）
人は1人ずつ紙（キャンバス）に描いて板に貼っている。重さは「人数」ではなく「**違う絵の枚数**」で決まる（描く時間＋GPU への転送）。だから違う絵を増やさない作りにしてある。
| 距離 | 描き方 | 見た目 |
|---|---|---|
| 6.5 m より近い | 毎フレームそのまま（まばたき・細かい動きすべて） | 変えない |
| 6.5〜16 m（`FAR`） | 歩きは1歩の周期を8コマ、作業は10段階に丸める（2コマ打ち相当） | ほぼ同じ |
| 16 m より遠い（`CROWD`） | **服の型ごとに1枚の絵を共有**：頭の形は型ごとに固定、まばたきなし（2px 未満で見えない）、光は3方向、歩幅は1/4刻み | 並べて比べても違いが見えない |
- 描いた絵は使い終わっても捨てず、200MB まで取っておく（`Pool.BUDGET`、古いものから捨てる）。
- 群衆の置き方の例（cast.ts）：`evacuees`（燃える稲むらの列に沿って神社へ走る70人の流れ）、`climbers`（石段を3列で登る22人）、`hilltop`（高台で振り返る人たち）。
- 型：`villager(0〜11)`・`laborer(0〜4)`・`villageKid(0〜2)`。群衆は `who(i)` / `LAB(i)` / `kid(i)` で型を回して置けば、自動で共有される。同じ見た目の人が複数いてよい。
- 計測（shot 11、102フレーム、1タブ）：
  | | 速さ | 新しく描いた絵 | 空きメモリの最低 |
  |---|---|---|---|
  | 群衆なし | 5.8 枚/秒 | 7 | 2.6 GB |
  | 群衆100人・前 | 3.4 枚/秒 | 3201 | 1.6 GB |
  | 群衆100人・丸め＋取っておく | 4.3 枚/秒 | — | 1.1 GB |
  | 群衆100人・型で共有（今） | **5.7 枚/秒** | **273** | 2.3 GB |
- 試し方：`node scripts/render-short.mjs InamuraShort out/bench/x.mp4 --frames 772-873 --props '{"crowd":100,"stats":true}'`（`crowd` は試し専用の避難の群衆、`stats` は描いた枚数を出す）。
- 画像ファイルの束（スプライトシート）は今は作らない：全部の型×動き×光を読み込むと 0.4〜1.5GB を食い、安定性が下がる。型をコードで共有すれば同じ効果が出る。動画をまたいだ再利用は、このコード（`templates/japan/`）で行う。

- 主役の背景になる建物は、**視線の消し込み（build.ts `inTheWay`）で消えないように** `placeModel` で置く。カメラの視線が正面まで届くと、主役の建物ほど消される（01_inamura の shot 5 で醤油屋が消えていた）。

### 既製品を入れるときのメモリの決まり（01_inamura で測定）
- 同じモデルを何度も置くときは、**形を共有した複製**（`fitModel` → `sharedModel().clone()`）。Batch に混ぜると軒数だけ形がコピーされ、メモリが増える（堤防の松14本＋家並みで、書き出し中の空きメモリが 0.2GB まで減った → 共有で 1.6GB、速さも 5.5 → 6.6 枚/秒）。
- 1つしか置かない主役の建物（醤油屋）は `placeModel` で Batch に入れてよい。
- 落としたモデルのテクスチャが大きすぎる時は `scripts/glb_shrink.py`で小さくする。今回の4つは元から 1024px 以下だった。
- 探し方：Sketchfab の API（`https://api.sketchfab.com/v3/search?type=models&q=...&downloadable=true`）で、ライセンス・三角形数・サムネイルを一覧にしてから選ぶ。ダウンロードは `~/.tts_keys.env` の SKETCHFAB_API_TOKEN（値は画面に出さない）。
